# The Holding Realty — Visual Contract v1.6

Owner-approved target: the dark terminal demo supplied in the Realty build chat on 2026-08-30.

## Dark-mode acceptance

- The production landing should read visually as the approved terminal, not as a generic marketing landing.
- Dense top navigation, left Realty rail, split physical/digital hero artwork, compact source-backed KPI row, two large world gateways, market-overview strip, twin physical/digital market boards, four visible records per board, capability rail and compact footer should fit together as one terminal composition.
- Typography, density and vertical rhythm should stay close to the reference: the page should feel useful before scrolling rather than spending the first screen on oversized prose.
- Physical World uses warm gold/architecture imagery; Digital World uses restrained violet/spatial imagery.

## Light-mode acceptance

- Theme toggle remains first-class and persistent.
- Light mode is an editorial luxury interpretation of the same truth/data contract, consistent with the separately approved light desktop/mobile references.

## Truth boundary

Visual parity does not authorize demo facts. Concept-only Total Value, 24H Volume, universal APR, fake listings or fake market movements must not be promoted to production.

Production values are derived from admitted Realty contracts. Missing data remains missing. Source-specific return semantics remain source-specific.

Decorative/owned market artwork is explicitly illustrative and must not pretend to be an exact property photo.

## Performance boundary

The landing should remain lightweight: one small shell runtime, the existing current market snapshot and local static visual assets. No property-media observer, new backend, collector, scheduler or paid API is justified by the visual shell.
