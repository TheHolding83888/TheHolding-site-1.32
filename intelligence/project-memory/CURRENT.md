## Owner product / architecture directives reinforced today

### Surface / substrate law

**Surface may only reveal what substrate can prove.**

Visible UI, metrics, graph edges, signals and Ask answers should be backed by real blockchain/protocol evidence, provenance, normalized state, history and explicit epistemic boundaries. No decorative AI-looking intelligence.

### Ferrari / Rolls-Royce law

Backend depth and visual quality are complementary. The goal is world-class engine under the hood **and** world-class surface/product experience.

### JARVIS / conversational capital north star

The Holding should progressively feel like a founder-aligned capital companion: the owner increasingly “talks to his capital.” This is not unrestricted autonomy or personality imitation. It means persistent context + live capital state + memory + reasoning + measurable capabilities + bounded authority.

Target question classes include:
- current company health/state;
- income today/month/year;
- protocol contribution;
- TVL and rankings;
- best/worst periods;
- APR/reward/performance history;
- reasons for changes;
- protocol activity/fees/volume relationships where measurable.

### No code-for-code law

Every new layer should add at least one real capability:
1. a new fact can be measured;
2. a new relationship can be proven;
3. a new question can be answered correctly;
4. a new decision/outcome can be evaluated better.

Capability must grow faster than complexity.

### Work-stack continuity

Owner audio/product thoughts do not reset unfinished engineering work unless priority is explicitly changed. Accept the new input as a constraint, then continue the active task from the same point.

### Performance law

Intelligence depth must grow without responsiveness degrading. Prefer precomputation, incremental updates, bounded traversal, indexes/caching and local degradation over global failure.
