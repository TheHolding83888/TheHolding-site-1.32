## 3. FIRST PRODUCTION EPISODE TYPES

v0.1 intentionally starts narrow and source-backed.

### Productive-rate changes

Examples:
- company Reference APR changes;
- source-bound previous/current rate observations.

Hard boundary:
A Reference APR increase does **not** by itself prove why yield rose.

Owner context remains:
`verified real-yield source + yield ↑ = positive economic signal`

But mechanism/source attribution must be proven before the system explains the cause of the increase.

### Reported-income progression

Examples:
- current-month cash-flow counters;
- current-month generated-income counters.

The compiler compares increments / increment velocity rather than naively treating a cumulative counter as an ordinary directional market series.

A negative cumulative-counter delta is treated as possible period reset/correction unless separate evidence proves economic loss.

### Measurement-coverage changes

Coverage/completeness improvements are valid observational episodes because they describe improvement in the system's ability to see the economic state. They are not direct investment-performance signals.

## 4. EPISTEMIC CONTRACT

The autonomous learner must preserve this ladder:

`exact observation`
→ `deterministic derived change`
→ `repeated candidate association`
→ `candidate hypothesis`
→ later testing / additional evidence
→ accumulated experience

It must **not** collapse these stages.

Hard laws:
- `changed-after != caused-by`;
- correlation != causation;
- temporal order != causality;
- candidate pattern != learned lesson;
- candidate pattern != prediction;
- candidate pattern != policy;
- candidate pattern != trade/allocation instruction;
- one source event creates at most one canonical episode;
- duplicate historical run membership must not create duplicate economic observations;
- all available run provenance is preserved;
- `unknown != zero`.

Causal edges remain forbidden by this layer.

---

## 5. SAMPLING / SELECTION-BIAS CONTRACT

`change-history.json` is event-triggered change history, **not a uniform periodic statistical sample of every unchanged moment**.

Therefore:
- absence of an event does not prove absence of change;
- repeated recorded directions do not equal market probabilities;
- support counts describe support among recorded qualifying events only;
- pattern frequency must not be presented as unconditional statistical likelihood;
- a future statistical layer would need explicit sampling methodology before probability language is allowed.

This guard was added before production merge specifically to prevent the Brain from over-interpreting event-history frequency.

---

## 6. GRAPH CONTRACT

Observational learning extends the canonical Neural Graph overlay.

It does **not** create:
- a second graph;
- a competing truth plane;
- an alternate source of economic facts.

Graph relations should preserve:
- source event identity;
- entity;
- metric;
- observation time/window;
- previous/current values where relevant;
- source keys / provenance;
- epistemic status;
- pattern support evidence.

Graph quality is judged by retrieval, explanation, historical comparison and provenance — not by raw edge/node growth.

## 8. RELATION TO OWNER EXPERIENCE

The Holding now has two complementary learning lanes:

1. **Owner Decision → Outcome Experience** — learns what the owner actually decided, why, and what later evidence showed.
2. **Autonomous Observational / World Experience** — learns deterministic historical episodes and repeated candidate associations from the life of companies/protocols/strategies.

Long-term target:

`current situation ↔ prior world episodes ↔ owner decisions ↔ later outcomes ↔ evidence-backed lessons`

These lanes may be linked only when identifiers, semantics and time horizons actually match. Similarity alone does not create causal or decision equivalence.
