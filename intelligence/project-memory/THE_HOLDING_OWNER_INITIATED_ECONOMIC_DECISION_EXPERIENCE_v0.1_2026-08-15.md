# THE HOLDING — OWNER-INITIATED ECONOMIC DECISION EXPERIENCE v0.1
## Production candidate — 2026-08-15

## Purpose

Extend the existing Decision & Outcome Learning system so a material economic decision authored by the Holding owner can enter the **same canonical append-only Decision Ledger** even when the Grounded Brain did not originate a decision-worthy case.

This is not a new brain, a second ledger, or execution authority.

Canonical path:

`owner decision -> exact coherent Cognitive Stack context -> append-only Decision Ledger -> open pre-outcome experience -> later explicit outcome review -> lesson only after evidence`

## Authority boundary

- decision author: human owner
- facts/evidence context: exact coherent Grounded Brain / Cognitive Stack bytes
- model authority: none
- wallet/signing/transaction authority: none
- capital execution authority: none
- repository/methodology/policy mutation authority from the decision record: none
- automatic lesson from an open owner decision: none

## Why this capability is earned

The existing production recorder accepts only current decision-worthy Grounded Brain cases. That protects Learning from data-hygiene noise, but it cannot represent a real capital-management choice that originates with the owner.

The Decision Experience canon already requires pre-outcome capture of rationale, expected outcome, evaluation criterion, review horizon, counterevidence and invalidation conditions. The next real owner decision therefore justifies a bounded ingestion path into the existing ledger instead of a parallel Experience store.

## First real candidate — Defitea reward harvest timing

### Choice
- Option A: harvest currently accumulated protocol-generated rewards now.
- Option B: continue accumulating.
- Owner decision: **defer harvest / continue accumulating**.

### Rationale
Continue accumulating through the end of August 2026 so a larger reward batch can be harvested. A larger batch should make Ethereum transaction costs less material relative to the value moved. Some rewards are token-denominated, so waiting also preserves possible upside rather than forcing an early conversion.

### Expected outcome
At the end-of-August review, Defitea should have a larger accumulated reward balance and a more economically meaningful harvest opportunity. The likely next path is to harvest most accrued rewards, consolidate them into one stablecoin, then decide from current evidence whether to strengthen an existing productive position or add a new balance-sheet asset.

### Intended use
Use generated income to strengthen the Defitea company balance sheet. No destination asset is pre-committed today.

### Evaluation criterion
At review, compare:
- accumulated protocol-generated reward value;
- token composition and current market/risk state;
- estimated Ethereum/network costs as a percentage of harvest value;
- security/claimability conditions;
- available reinvestment opportunities;
- whether the larger batch creates a materially better capital-allocation decision than harvesting immediately on 2026-08-15.

A favorable token-price move alone does not prove the original decision was good; decision quality and outcome quality remain separate.

### Review condition
Primary review date: **2026-08-31**.

Review earlier if a material condition changes.

No minimum USD amount is invented because the owner specified a date-oriented review rather than a hard value threshold.

### Counterevidence
Waiting leaves token-denominated rewards exposed to price downside and may extend protocol/claim risk. Ethereum fees can also fall before month-end, creating a cheaper earlier harvest opportunity. Token upside is possible, not guaranteed.

### Invalidation / early-review condition
Revisit before month-end if any of the following becomes material:
- protocol, claim, security or smart-contract risk increases;
- reward-token quality or price deteriorates enough to change the risk/reward;
- unusually favorable network fees make an earlier harvest economically compelling;
- Defitea has a time-sensitive balance-sheet need;
- a clearly superior reinvestment opportunity appears and requires realized liquidity.

### Deferred alternative
Harvest now, convert rewards immediately into stable value, and reinvest earlier.

### Outcome
**OPEN.**

No lesson exists yet. The decision becomes learning evidence only after a later observed/reported outcome and separate decision-quality / outcome-quality review.

## Peer strategy context — provenance rule

The owner also reports that **YieldRing** and **Dynaz** follow broadly similar reward-accumulation thinking: allow rewards to build for longer periods, potentially months, because some rewards retain token upside and because batching can reduce the relative burden of Ethereum transaction costs before later reinvestment.

This information is useful **peer context**, but it is not automatically equivalent to the Defitea owner decision.

Until attributable evidence is captured, classify it as:

`owner-reported peer strategy context`

Do not:
- insert it into the Holding owner's Decision Ledger as if authored by the Holding owner;
- treat it as verified direct owner testimony unless provenance is supplied;
- convert it into Founder Decision DNA;
- infer an outcome or lesson.

If later supplied with the exact company, decision author/source, decision timing, rationale, intended action and outcome, it can become stronger peer experience evidence with explicit provenance.

## Conversation / operating journal rule

Founder/operator conversations are high-value learning material when classified before persistence.

Preferred classes:
1. **Owner Decision** — an actual choice under trade-off; strongest pre-outcome Decision Experience.
2. **Owner Thesis / Hypothesis** — belief or expectation, not yet a decision.
3. **Owner Intent / Plan** — intended future action, still changeable.
4. **Peer Owner Strategy** — attributed external operating view.
5. **Observation / Fact** — evidence about what happened or exists.
6. **Outcome Update** — what happened after a recorded choice.
7. **Reversal / Superseding Decision** — a deliberate change of mind with reason.

Conversation is therefore a useful operating journal, but not every sentence becomes policy, Founder DNA or calibrated learning.

## First implementation boundary

v0.1 records owner-initiated economic decisions as:
- pre-outcome;
- `experience.status = open`;
- unscored;
- exact-context-bound;
- non-executable.

It deliberately does **not** add an automatic settlement rule before the first real review is reached. A future explicit owner-outcome review path should be added only after a real open decision reaches review and demonstrates the need.
