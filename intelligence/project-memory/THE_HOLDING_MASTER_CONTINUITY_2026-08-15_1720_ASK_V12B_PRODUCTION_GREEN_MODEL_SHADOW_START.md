## 5. WHAT v1.2B NOW GUARANTEES IN PRODUCTION

`natural language → structured intent candidate → Intent Contract Firewall → deterministic source-bound retrieval → grounded answer → Answer Contract → Output Guard`

`0.1-intent-contract-firewall`

- `version`
- `intent`

## 7. NEXT PRIMARY OBJECTIVE — MODEL-ASSISTED INTENT SHADOW MODE

Now that the firewall is production-proven, the next justified primary objective is:

**Model-assisted intent parsing in shadow mode.**

Initial architecture:

`raw user language`
→ `model intent candidate (UNTRUSTED)`
→ `Intent Contract Firewall`
→ `shadow comparison with deterministic router`
→ `NO model answer authority`

The deterministic Ask router remains the only live answer path during the shadow phase.

### Shadow phase goals

1. inspect existing repository/runtime/provider infrastructure before choosing any model dependency;
2. do not hard-code or expose secrets;
3. introduce a provider-agnostic adapter where possible;
4. send only the raw query / minimum language context needed for intent understanding;
5. require structured candidate output only;
6. validate every candidate through the production Intent Contract Firewall;
7. reject malformed/over-authoritative candidates fail-closed;
8. compare model intent against deterministic routing on noisy RU/EN, paraphrases, typo pressure and broad-sweep classes;
9. store shadow evidence as ephemeral verification evidence, not as new factual truth;
10. preserve Semantic Safety and false-MEASURED = 0;
11. unsupported objects (purpose drift, realised cash flow, maturity) must remain UNKNOWN until canonical objects exist;
12. execution/transaction commands remain `executionAuthority = none`;
13. do not visibly promote Ask maturity until shadow evidence demonstrates real language-generalization improvement.

### Important model boundary

A future model may help with:

- paraphrase understanding;
- RU/EN/noisy language;
- intent classification;
- entity recognition;
- timeframe/comparison/metric extraction.

A future model may NOT independently:

- invent balances/APR/APY/rewards/performance/cash flow;
- select canonical facts;
- assign factual confidence;
- create missing purpose/maturity/history;
- bypass Semantic Safety;
- bypass Output Guard;
- move capital;
- sign transactions;
- mutate methodology, security policy or production code;
- grant itself authority.
