# 9. SECURITY SENTINEL PRECISION CLEANUP — PRs #255, #256

## PR #255 — Puppeteer `$eval` / `$$eval` false-positive fix

Merge:
`2eb37ab776728c260d99bec88db8825ff14b67ff`

Root cause:
JavaScript-eval detector used a pattern equivalent to `\beval\s*\(`. Because `$` is non-word, Puppeteer `page.$eval(` and `page.$$eval(` were incorrectly classified as dangerous bare `eval(`.

Fix made detection context-aware so:
- `page.$eval(` → not a JavaScript eval finding;
- `page.$$eval(` → not a JavaScript eval finding;
- real `eval(` → still detected;
- property/bare dangerous eval semantics remain guarded under the chosen policy.

Regression explicitly protects both negative and positive examples.

## PR #256 — shell `eval` command precision

Merge:
`d6a304dd934f850e74d2e86dd85ed7b7f1279907`

A second false-positive class was found: the shell detector matched the word `eval` inside arbitrary YAML/prose text such as a test description, not only an executable shell command.

Fix made shell-eval detection command-aware while keeping real `eval "$value"` detectable.

Regression fixture avoids embedding the dangerous command literally inside the verifier itself; it constructs the test command dynamically so Sentinel sees exactly one intended temporary fixture finding.
