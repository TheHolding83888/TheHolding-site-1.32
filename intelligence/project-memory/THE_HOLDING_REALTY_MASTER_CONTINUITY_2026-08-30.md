The Holding is a Capital Operating System and persistent intelligence/memory/governance layer for sovereign onchain companies and funds.

# 3. OWNER PRODUCT VISION

The Holding Realty should become a very large, premium real-estate discovery and intelligence portal.

Useful analogies for product ambition:

- **ЦИАН / Avito Real Estate / Auto.ru** for breadth, browsing and deep object navigation;

The public experience should feel simple and premium even if the substrate becomes sophisticated.

# 4. TWO WORLDS — ONE REALTY TERMINAL

Realty deliberately includes two different property universes:

## Physical World

Tokenized or digitally accessible real-world property:

- fractional rental property;
- tokenized development projects;
- whole-property transaction/title rails;
- future RWA property structures;
- potentially tokenized square meters, revenue rights, equity or title depending on provider.

## Digital World

Metaverse / virtual real estate:

- LAND;
- estates;
- parcels;
- world-specific property assets;
- source-market asks/offers/floors/sales.

These worlds share discovery UX but **must not be semantically homogenized**.

Physical return/cash-flow metrics and virtual-land marketplace metrics are different economic objects.

A mature Realty portal can visually connect the worlds while preserving different data contracts.

# 6. TRUTH / DATA LAWS — NON-NEGOTIABLE

Realty inherited The Holding truth culture from the start.

Hard laws:

- `UNKNOWN != ZERO`
- missing field != zero;
- not disclosed != zero;
- source unavailable != zero;
- stale snapshot != live data;
- ask != best offer;
- ask != collection floor;
- floor != last sale;
- project value != minimum entry;
- minimum entry != property value;
- estimated/projected return != realised yield;
- Average Rental Yield != universal APR;
- source projection != cash actually earned;
- aggregation != homogenization;
- market presence != listing coverage;
- city anchor != property boundary;
- source media URL != permission to publicly republish media;
- public data availability != blanket legal permission for unrestricted scraping/commercial reuse.

If a value cannot be reproduced/verified, do not invent it.

If a field is unavailable, present an elegant absence such as:

- `Not disclosed`
- `Source unavailable`
- `Tracking soon`
- `—`

Do not use fake global Realty TVL, fake global 24h volume, fake valuation totals or decorative KPIs.

# 7. DATA / SOURCE STRATEGY — FREE-FIRST, SOURCE-FIRST

The owner explicitly wants Realty to avoid unnecessary paid API dependencies.

Preferred hierarchy:

1. first-party provider pages/data;
2. public protocol/market endpoints where lawful and stable;
3. public blockchain/contracts/events when they are the strongest source;
4. source marketplaces for digital property;
5. existing verified The Holding Market Data/oracle infrastructure when USD conversion becomes necessary;
6. paid API only if a real capability gap justifies it later.

Do **not** create a dedicated CoinGecko dependency simply because an asset has a token price.

For property-market prices and object data, the source marketplace/provider is often more authoritative than a generic crypto price service anyway.

If later onchain token conversion is needed, prefer reusing The Holding's existing verified market-data authority rather than building a second price engine inside Realty.
