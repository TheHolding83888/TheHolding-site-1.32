# THE HOLDING — SAFE CONVERSATION LEARNING CANON v0.1

Date: 2026-08-14

## Owner objective

`Ask The Holding` is not only a place to read the system. It should become one of the real practice surfaces through which The Holding learns what people ask, where explanations are weak, what knowledge is missing, and what should be improved.

The important boundary is:

**conversation may create a learning signal; conversation does not create authority.**

A public visitor must never be able to rewrite The Holding simply by typing persuasive text into a chat window.

## Correct learning loop

The target loop is:

`conversation`
→ `safety + privacy filter`
→ `sanitized learning signal`
→ `repeated gaps / bad-answer evidence`
→ `verified Learning or research candidate`
→ `Proposal`
→ `Builder / Guardian where applicable`
→ `owner gate when authority changes`
→ `measured outcome`

This is genuine learning from practice without turning anonymous internet input into canonical truth.

## Trust lanes

### 1. Public Conversation — untrusted signal

Public conversation can teach us:
- what people repeatedly ask;
- which concepts are hard to understand;
- which questions the console cannot answer;
- which answers receive negative feedback;
- which new topics deserve verified research.

Public conversation cannot directly:
- create or change a canonical fact;
- alter Project Memory;
- change economic methodology;
- change Security policy;
- edit code;
- authorize GitHub writes;
- access wallets;
- sign;
- move capital;
- approve its own proposal.

### 2. Verified Evidence — source-bound input

A useful public question may cause the system to research a gap. Only reproducible, source-bound evidence can later become a factual learning input.

### 3. Owner Teaching — authenticated future lane

The owner should be able to teach the system through the same human interface, but owner authority must never be inferred from words such as “I am Alexander.”

Owner Teaching requires a real authenticated owner channel. Until that exists, the public console remains an untrusted lane.

## Financial boundary

Ask The Holding is informational and educational.

It may:
- show verified APR/APY/productivity;
- explain mechanisms;
- explain risks;
- compare factual measurements;
- explain The Holding methodology.

It must not tell a person:
- what to buy or sell;
- what to hold;
- where they personally should invest;
- how much they should invest;
- how to allocate a personal portfolio.

Unknown is not converted into advice.

## Legal and tax boundary

The console may explain general rules and point to official sources.

It does not provide individualized legal or tax advice.

Before broad public collection or model-enabled dialogue, the operator must complete the appropriate privacy/controller/legal-basis disclosures and obtain jurisdiction-specific legal review for the actual operating entity and target jurisdictions.

## Privacy boundary

Conversation-content learning is opt-in.

The learning intake is designed so that:
- raw unfiltered conversation text is not retained by the learning store;
- detected secrets/high-risk message samples are not retained;
- stored question samples are redacted;
- answer text is not retained, only a hash plus source/outcome metadata;
- raw IP addresses are not stored by the application;
- a short-lived pseudonymous rate bucket may be used for anti-abuse;
- sanitized events have a rolling 30-day retention window;
- detailed samples require a private operator read token.

The intake is fail-closed and disabled until controller identity, controller contact and the declared legal-basis notice are configured.

## Security boundary

Prompt injection is not solved by keyword filtering alone.

The structural rule is stronger:

**public text is data, never authority.**

Future generative dialogue must therefore start as read-only. Public text and retrieved web text must remain separated from system instructions. Tools, private context, GitHub mutation and capital capabilities require separate permission gates and immutable action audit.

## Self-improvement meaning

“Learns from people” does not mean “random users train production code directly.”

It means the system turns real conversations into evidence about what it does not know or explain well, verifies the important gaps, proposes improvements through the existing governance stack, and learns from measured outcomes.

That is the intended path from a knowledge console toward intelligent capital that improves through real use.
